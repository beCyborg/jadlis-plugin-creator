# У тебя плагин обновился, а у того, кто его поставил, осталась старая версия — и не узнают об этом оба

Выпуск идёт по одному списку: офлайн-префлайт, `claude plugin validate --strict`, версия в
единственном месте, changelog, тег, релиз и установка в чистое окружение — а получателю выдаётся
строка, которую он выполняет у себя.

```
claude plugin marketplace add https://github.com/beCyborg/jadlis-hub
claude plugin install jadlis-plugin-creator@jadlis
```

Ключи не нужны; нужны git, авторизованный `gh` и сам `claude plugin` — на них держатся тег, релиз и
проверочная установка.

![Одна дорожка от папки с работой до опубликованного релиза, и последняя стрелка уходит к тому, кто плагин уже поставил](docs/img/hero-jadlis-plugin-creator.webp)

Текстом: слева папка с готовой работой, справа опубликованный релиз, между ними шаги, каждый из
которых закрыт проверкой, а последняя стрелка ведёт к человеку, у которого плагин уже установлен.

Это моё рабочее место, выложенное как есть, а не продукт: чем перестал пользоваться — убрал.

## Было → стало

| Руками | Чатом с ИИ | Этим плагином |
|---|---|---|
| **Что доезжает до получателя.** Правка внесена, коммит запушен — и выпуск считается сделанным. | Расскажет, как устроен `plugin.json`, но твоего дерева не видит и про версию как ключ кеша не напомнит. | Версия бампится в `plugin.json` и только там: совпала с установленной — обновление молча пропускает плагин, поэтому бамп стоит в одном шаге с правкой. |
| **Где лежат правки.** Клон маркетплейса лежит под рукой, править удобнее всего прямо в нём. | Путей не различает и предложит редактировать там, где открыто. | Работа идёт в отдельном рабочем клоне, ветка пушится сразу, операции `claude plugin` — только после пуша: фоновое обновление сбрасывает клон маркетплейса к origin вместе с локальными ветками. |
| **Что значит «проверено».** Глазами по JSON и по структуре папок, на что взгляда хватило. | Скажет, что схема выглядит правильной. | Сначала офлайн-префлайт по домашнему стандарту, потом `claude plugin validate --strict` во всех режимах, применимых к раскладке, потом установка в чистое окружение с вызовом контрольного скилла: валидатор — не загрузчик. |
| **Как выпускается версия.** Шаги идут по памяти, а пропущенный не виден до жалобы получателя. | Перечислит шаги, но не проверит, создан ли тег и опубликован ли релиз. | Тег `{plugin-name}--v{version}` ставится командой `claude plugin tag --push`, которая требует чистого дерева и согласованных манифестов; поверх тега — релиз через `gh`, а строка обновления повторяется в заметках релиза. |
| **Переезд старого репозитория.** Общий маркетплейс появился, а установки у людей остались на старом. | Посоветует переименовать плагин — и установки отвалятся. | Имя плагина не меняется, переименование идёт через append-only карту `renames`, старый маркетплейс остаётся читаемым, пока получатели не переехали, а плагинам с внешним источником заранее сказано про переустановку. |

## Как это работает

![Задача уходит в один из четырёх режимов, префлайт и валидация закрывают путь к бампу версии, дальше тег, релиз и проверочная установка](docs/img/how-jadlis-plugin-creator.webp)

На входе — папка с готовой работой или репозиторий, который пора выпустить.
Внутри — маршрут по режиму: каркас по домашнему стандарту, офлайн-префлайт и `claude plugin
validate --strict`, бамп версии с changelog, тег и релиз, перенос в общий маркетплейс.
На выходе — опубликованный релиз и строка обновления, которую выполняет получатель.

Текстом: задача → выбор режима (собрать, проверить, выпустить, перенести) → префлайт и валидация →
версия, changelog, тег, релиз → установка в чистое окружение → строка обновления у получателя.

Ведёт всё один скилл, инлайн и без субагентов: операции git и `gh` последовательные и завязаны на
состояние рабочего дерева. Режимов четыре — собрать каркас, проверить, выпустить, перенести старый
репозиторий в общий маркетплейс; на неоднозначной задаче скилл не угадывает, а задаёт один вопрос с
этими четырьмя вариантами. Факты о манифестах, типах компонентов, маркетплейсах и релизе он не берёт
из памяти: рядом лежат справочники, и режим открывает тот, что относится к вопросу. Офлайн-префлайт
ловит то, что канон `claude plugin validate` не ловит: версия объявлена в единственном месте,
`$schema` стоит в обоих манифестах, LICENSE на месте, `plugins[]` отсортирован и без дублей, внешний
источник приколот полным SHA коммита, `.mcp.json` и `hooks/hooks.json` разбираются как JSON, у хуков
есть внешняя обёртка, а `${CLAUDE_PLUGIN_ROOT}` в шелл-командах закавычен. Находки выдаются списком
с разделением на ошибки и предупреждения и с исправлением на каждую.

## Установка и первый запуск

**а) Текст для вставки агенту.** Скопируй целиком в чат Claude Code:

```
Ты — установщик. Поставь на этот Mac плагин jadlis-plugin-creator из маркетплейса jadlis.
Выполни ровно эти команды, дословно, ничего не сокращая:
1. claude plugin marketplace add https://github.com/beCyborg/jadlis-hub
2. claude plugin install jadlis-plugin-creator@jadlis
3. claude plugin list — покажи мне строку про jadlis-plugin-creator и его версию.
Ключей этот плагин не просит. Проверь и скажи мне отдельно, есть ли на машине git,
python3 и gh с авторизацией (gh auth status): без них шаги тега, релиза и проверочной
установки не пройдут.
Перед каждой командой покажи её мне целиком и дождись «да». Сказал «нет» — не выполняй,
скажи, что именно пропустил, и иди дальше.
Команда вернула ошибку — остановись, покажи вывод, к следующей не переходи.
```

**б) Команды руками.**

```
claude plugin marketplace add https://github.com/beCyborg/jadlis-hub
claude plugin install jadlis-plugin-creator@jadlis
claude plugin list
```

Первая команда ничего не ставит — она добавляет маркетплейс. Ставит только вторая, и снимается
она одной строкой: `claude plugin uninstall jadlis-plugin-creator@jadlis --keep-data`.

**в) Короткая команда.** Открой Claude Code в рабочем клоне своего репозитория и набери:

```
/plugin-creator <задача>
```

Например: `/plugin-creator проверь плагин перед релизом`. Не находится — сверь имя строкой
`claude plugin list`. Запускать в клоне маркетплейса под `~/.claude/plugins/marketplaces/` не надо:
фоновое обновление стирает оттуда правки.

## Границы, стоимость, обновление

**Чего не делает.** Не пишет и не улучшает содержание скиллов — интервью, устройство, эвалы и
доводка описания живут в `skill-builder`, здесь упаковка и выпуск уже готовой работы. Не подаёт
плагин в официальный и community-каталоги Anthropic: туда подают через их веб-формы. Не водит по
интерфейсу маркетплейса — это официальная документация. Не чинит найденное само: отдаёт список
находок с исправлением на каждую и правит только по просьбе. И не отменяет проверку живой
установкой — зелёный валидатор не значит, что плагин загрузится, поэтому установка в чистое
окружение стоит отдельным шагом.

**Что нужно.** Ключей нет и платных сервисов нет — работает на подписке Claude Code. Из внешнего
нужны git, `gh` с авторизацией, сам `claude plugin` и python3 для офлайн-префлайта: без них тег,
релиз и проверочная установка не проходят. Нужен и отдельный рабочий клон репозитория — правки в
`~/.claude/plugins/marketplaces/<имя>/` стирает фоновое обновление, вместе с локальными ветками.

[уточнить] — минимальные версии git, `gh` и python3 в репозитории не зафиксированы.

**Порядок расхода токенов.** Прогон лёгкий: один скилл, инлайн, без субагентов и без MCP-серверов.
Справочники читаются по одному — тот, что относится к вопросу, а не все сразу. Дороже прочего
обходится проверочная установка: она поднимает отдельную сессию в чистом конфиге и вызывает там
контрольный скилл.

**Проверено там, где я работаю:** мой Mac, моя подписка, мои репозитории. Где ещё это работает —
[уточнить].

**Условия использования.** Лицензия Apache-2.0 — текст в файле [LICENSE](LICENSE).

**Обновление.** У стороннего маркетплейса авто-обновление на твоей стороне выключено: пока не
запустишь первую команду, у тебя остаётся та версия, которую ты поставил.

```
claude plugin marketplace update jadlis
claude plugin update jadlis-plugin-creator@jadlis
claude plugin list
```

Переустановка, если что-то встало криво:

```
claude plugin uninstall jadlis-plugin-creator@jadlis --keep-data && claude plugin install jadlis-plugin-creator@jadlis
```
